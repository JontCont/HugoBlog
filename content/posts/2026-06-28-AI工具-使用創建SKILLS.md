## 前言

在現代開發流程中，我們越來越依賴 AI 助手（如 GitHub Copilot、Antigravity、Cursor）來處理重複性高、但又需要符合專案規範的工作，例如：

- 生成符合團隊標準的 Git Commit
- 建立結構一致的技術文章
- 套用既定 coding style 或架構模式

問題在於：**這些規範往往只能存在於 Prompt 中，難以重複使用，也難以在團隊中共享。**

這正是 **Agent Skills** 出現的原因。

透過 Skills，我們可以把「如何做一件事」封裝成可版本化、可分發、可重用的模組，讓 AI 不只是回答問題，而是**直接執行標準化工作流程的 Agent**。

但新的問題也隨之出現：**不同 AI 工具之間的規則與技能格式完全不相容。**

這篇文章會帶你解決兩件事：

- 如何建立一個可重用的 AI Skill
- 如何用 `rules-bridge` 一次同步到所有 AI 工具

***

## 一、為什麼 Skills 正在取代 Prompt？

過去我們習慣用 Prompt 驅動 AI，但在實務上會遇到幾個問題：

- Prompt 不穩定（容易受模型或上下文影響）
- 難以版本控制
- 團隊難以共享與標準化

而 **Agent Skills** 本質上解決的是「工程化」問題：

- Prompt → 即時輸入
- Skill → 可維護的系統模組

這帶來幾個關鍵轉變：

- **可版本化**：技能可以跟著 Git 管理
- **可組合**：不同技能可以疊加使用
- **可觸發**：AI 可依語意自動選擇技能
- **可執行**：可串接 scripts，真正落地自動化

實務上，你可以把 Skills 理解為：

> 「給 AI 用的 runbook + toolchain」
> 
> 💡 **名詞解釋**：
> - **Runbook（工作手冊/運維手冊）**：指的是指導如何執行特定任務或解決問題的「標準作業程序（SOP）」。對 AI 而言，這對應到 `SKILL.md` 裡的執行步驟與規範指引。
> - **Toolchain（工具鏈）**：指的是為了完成某一工作流程，所串接使用的一整套開發工具或腳本集合。對 AI 而言，這對應到 `commands/` 與 `scripts/` 下供其呼叫並自動化執行的工具與程式。

## 二、真正的痛點：工具之間完全不互通

當你開始在專案中使用 Skills，很快會遇到一個現實問題：

**每個 AI 工具都有自己的規則系統，而且彼此不相容。**

常見差異如下：

- GitHub Copilot  
  - `.github/copilot-instructions.md`  
  - `.github/skills/`

- Antigravity / Codex CLI  
  - `.agents/AGENTS.md`  
  - `.agents/skills/`

- Cursor  
  - `.cursor/rules/*.mdc`（含 YAML frontmatter）

這代表：

- 同一份技能需要複製多份
- 規則需要手動同步
- 很容易出現版本不一致

這就是 **rules-bridge 解決的核心問題**：

> 「讓你只維護一份來源，其餘全部自動同步」

***

## 三、什麼是 Agent Skill？

一個完整的 Skill 通常包含三個部分：

### 1. SKILL.md（核心）

- 定義名稱、描述、觸發關鍵字
- 描述 AI 應該如何執行任務

### 2. commands/（選用）

- 提供 `/command` 形式的操作入口
- 適合常用流程（如 `/git`, `/deploy`）

### 3. scripts/（選用）

- 真正執行的腳本（shell / node / powershell）
- 讓 AI 不只是「說」，而是「做」

***

## 四、Instructions 與 Skills 的生命週期與呼叫機制

在實務上，雖然 GitHub Copilot、Antigravity 或其他 AI 助手都有類似的規則與技能機制，但它們的**呼叫方式**與**生命週期（Lifecycle）**各不相同，這會直接影響到 AI 的執行品質。

### 1. Skills 的兩種呼叫機制

AI 助手通常透過以下兩種方式呼叫並載入 Skills：

1. **自然語言觸發（語意載入）**：AI Agent 在啟動時會預先掃描所有 Skills 的 `SKILL.md` 描述區塊（YAML frontmatter 中的 `description`）。當使用者用自然語言輸入時，Agent 會透過語意分析判定是否相符。一旦相符，就會動態載入該 Skill 的詳細說明。
2. **斜線指令觸發（Slash Command）**：使用者手動輸入如 `/rules-bridge` 或 `/git`。這種方式是強制的，AI 會繞過語意判定，直接載入該指令所宣告的規範、並執行背後的腳本。

---

### 2. 生命週期對 AI 品質的決定性影響

這也是為什麼 rules-bridge 要強調跨工具適配的原因。不同工具的生命週期設計，會直接影響 AI 能不能「聽懂人話」：

- **全域常駐型生命週期（如部分舊版 Copilot）**：將所有規則（Instructions/Rules）一次性全部塞入 System Prompt。這會導致 Context 被大量無關內容污染。AI 容易分心（產生幻覺），執行速度變慢，且常常因為 Token 限制而漏掉重要指示。
- **動態隨取隨用生命週期（如 Antigravity / Claude Code）**：技能在平常是「靜態」的，不佔用任何 Token 空間。只有在偵測到特定關鍵字（自然語言）或斜線指令時，才會在當下對話中**動態加載**對應的 `SKILL.md` 內容；任務完成後便將其移出 Context。這種動態生命週期能保持 Context 乾淨、降低干擾，從而大幅提高 AI 的產出品質與穩定度！

## 五、實作：建立一個 add-post Skill

### Step 1 — 建立結構

我們以 **Antigravity** 為主要範例。由於不同 AI 工具的技能存放路徑有所差異（詳細對照請參考 [二、真正的痛點：工具之間完全不互通](#pain-points)），在 Antigravity 中，我們需要將技能建立在 `.agents/skills/` 底下：

> **小提醒**：如果要創建 skills 可以直接用自然語言跟AI說要使用哪個 AI 工具即可，例如 `請使用 antigravity 來幫我建立 skills`，這會自動幫你建立 `.agents/skills/`、`.agents/AGENTS.md` 等必要結構，並完成初步的環境設定。

```text
.agents/skills/add-post/
├── SKILL.md
└── example-post.md
```

***

### Step 2 — 撰寫 SKILL.md

```yaml
---
name: add-post
description: |
  協助建立格式正確的技術部落格文章。
  關鍵字：新增文章, 撰寫文章, add post
---

# Skill: 建立技術文章

## 任務
在 `content/posts/` 建立新文章。

## 規範
1. 必須包含 TOML Frontmatter
2. 標題格式：`【分類】- 主題`
3. 檔名格式：`YYYY-MM-DD-分類-主題.md`
```


實務建議：

- description 一定要寫「關鍵字」
- 規範盡量明確（避免 AI 自行猜測）
- 可以附 example file 提升穩定度


> **小提醒**：SKILL.md 是讓 AI 了解如何執行任務的說明檔， 通常會包含以下資訊：
> 1. name：skill 的名稱 (同 slash command 的名稱)
> 2. description：skill 的描述 (自然語言，用於觸發 skill)

## 六、套用別人的 SKILL

當你做完一個 SKILL 想要讓其他人使用或是單純想要放在 github repository 可以考慮以下做法

範例 : [rules-bridge](https://github.com/JontCont/rules-bridge)

### Step 1 — 安裝與技能結構

你可以透過 `skills-cli` 來在專案中套用別人寫好的 SKILL。安裝方式非常簡單，你只需要知道該 GitHub 儲存庫的 **Username（使用者名稱）** 以及 **Repository（專案名稱）** 即可進行安裝。

以安裝我們的 `rules-bridge` 為例（儲存庫路徑為 `JontCont/rules-bridge`），執行以下指令會自動引導你選擇要裝載的 AI 助手（例如 GitHub Copilot、Antigravity 等）：

```bash
npx skills add JontCont/rules-bridge
```

**互動式安裝畫面範例：**

> **小提醒** : selected 需要按下 space bar 來選擇，有被選中的話後面會出現星號 `*`

```text
◇  Which agents do you want to install to?
│  Amp, Antigravity, Antigravity CLI, Cline, Codex, Cursor, Deep Agents, Gemini CLI, GitHub Copilot, Kimi Code CLI, OpenCode, Warp, Zed, Autohand Code CLI, Claude Code
│                   
◇  Installation scope
│  Project                                                               
│                                          
◇  Installation method                     
│  Symlink (Recommended)                                         
                                           
◇  Installation complete                                         
└  Done!  Review skills before use; they run with full agent permissions.
```

**建議技能呈現結構（Project Structure）：**

一個標準且健壯的 Skill 專案，建議依循以下目錄結構進行組織呈現：

```text
rules-bridge/
├── SKILL.md                   # Skill 中繼資料與指引說明 (核心)
├── commands/
│   └── rules-bridge.md        # 斜線指令 (/rules-bridge) 的定義檔 (選用)
├── scripts/
│   └── convert.sh             # 實際執行轉換與鏡像同步的邏輯腳本 (選用)
├── README.md                  # 技能使用說明文件
└── LICENSE                    # 專案授權條款
```


## 七、這個架構真正的價值

當你導入這套流程後，會出現幾個質變：

- **單一來源（Single Source of Truth）**
- **跨工具一致行為**
- **技能可累積成團隊資產**
- **新成員 onboarding 成本大幅降低**

更重要的是：

> 你開始在「設計 AI 系統」，而不是「寫 Prompt」
